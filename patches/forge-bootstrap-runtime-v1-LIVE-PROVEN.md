# Forge BOOTSTRAP runtime patch v1 - Live-Proven Bank

Status: LIVE-PROVEN on Forge/OpenClaw OpenAuth/Codex app-server path  
Date: 2026-09-22  
Base OpenClaw fork commit: `c407f496bf4d94411f5aba6991321239dc49e2e7`

## Purpose

Bank Forge's BOOTSTRAP as an OpenClaw runtime patch, not as a Discord Monitor plugin.

The split is intentional:

- **BOOTSTRAP = plumbing and hard runtime contracts** - Forge identity, Discord delivery behaviour, exact `NO_REPLY` transport contract, DM/server distinction, and fundamental boundaries.
- **AGENTS.md = reasoning and social judgement** - when to speak, Chat vs Support, tone, support verification, moderation judgement, and conversational behaviour.
- The Discord Monitor plugin should not own or rewrite BOOTSTRAP.

The live patch is stored in:

`patches/forge-bootstrap-runtime-v1.ps1`

## Why this is a runtime patch

Forge's current BOOTSTRAP is generated by `buildDeveloperInstructions()` in the compiled OpenClaw/Codex `thread-lifecycle-*.js` runtime.

On the live Windows deployment there are two relevant runtime copies:

1. Global OpenClaw:
   `%APPDATA%\npm\node_modules\openclaw\dist\thread-lifecycle-*.js`
2. Forge project-local Codex:
   `%USERPROFILE%\.openclaw\npm\projects\...\node_modules\@openclaw\codex\dist\thread-lifecycle-*.js`

Both must carry the same Forge BOOTSTRAP. Patching only one copy can produce model/session-dependent behaviour.

The patcher discovers both copies by function/content anchors rather than depending on the build hash in the filename.

## Current live-proven behaviour

The 2026-09-22 patch:

- removes the old `mostly lurk / be extremely selective` server pressure;
- delegates speaking judgement to AGENTS.md;
- keeps exact `NO_REPLY` as the transport-level silence contract;
- allows open-room conversation without requiring a direct mention when AGENTS permits it;
- preserves normal DM behaviour;
- keeps the serious-safety human-admin boundary in the trusted BOOTSTRAP as a hard fail-safe.

A fresh Luna native thread was then verified to contain the new BOOTSTRAP at its initial developer prompt, with the old server-speaking paragraph absent.

## How to change BOOTSTRAP going forward

Until BOOTSTRAP becomes a real workspace file, treat `patches/forge-bootstrap-runtime-v1.ps1` as the canonical editable patch.

1. Edit **only** the `$ForgeBootstrapFunction` block for ordinary wording changes.
2. Keep runtime mechanics in BOOTSTRAP. Put social/support reasoning in the Forge workspace `AGENTS.md` instead.
3. Run a preflight first:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\patches\forge-bootstrap-runtime-v1.ps1 -PreflightOnly
   ```

4. Check that every discovered candidate passes `node --check`.
5. Apply:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\patches\forge-bootstrap-runtime-v1.ps1
   ```

6. The patch does **not** restart the Gateway. Restart once manually:

   ```powershell
   openclaw gateway restart --safe
   ```

7. Do not immediately restart again during the normal safe-restart handoff. Wait for it to settle, then verify RPC if needed.
8. Validate with a fresh native test thread when you specifically need proof of the initial BOOTSTRAP snapshot. For normal AGENTS.md edits, a new native thread is not required.

The patcher creates timestamped originals/candidates plus a rollback script on the Desktop before it mutates live runtime files.

## Important verification rule

A rollout JSONL is append-only.

The original developer prompt at the start of an existing native thread remains in that file forever. Therefore:

- finding old BOOTSTRAP wording near the beginning of an old rollout does **not** prove the current runtime patch failed;
- for an initial-thread proof, inspect a genuinely fresh native thread;
- for an existing thread, use current turn-start/developer-instruction diagnostics rather than searching the entire rollout for historical text.

## When to stop and re-audit

The patch intentionally fails closed if the expected `buildDeveloperInstructions(params, options = {})` function shape is no longer present exactly once.

If a future OpenClaw update changes that function or removes the `buildDeferredDynamicToolManifest` anchor:

- do not weaken the regex until the new source/runtime has been inspected;
- re-locate the developer-instruction builder;
- confirm which global and project-local runtime copies the Gateway actually loads;
- update this patch and this document together.

## Longer-term cleanup

The preferred later architecture is to make BOOTSTRAP a real workspace file, for example:

`%USERPROFILE%\.openclaw\workspace\BOOTSTRAP.md`

Then `buildDeveloperInstructions()` should become a small loader/composer rather than holding Forge's editable BOOTSTRAP text in compiled JavaScript.

At that point:

- `BOOTSTRAP.md` becomes the editable source of truth;
- `AGENTS.md` remains the reasoning/behaviour layer;
- startup should fail loudly if BOOTSTRAP is required but missing;
- this runtime patch can be retired.
